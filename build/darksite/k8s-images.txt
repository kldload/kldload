# Container images baked into the darksite for offline Kubernetes.
#
# Pulled by build/darksite/pull-k8s-images.sh during the ISO build and saved
# as tarballs under /root/darksite/k8s-images, then imported into the golden
# image's containerd so a cluster can come up with no network at all.
#
# WHY the list looks the way it does — three lessons, all from one install:
#
#   1. It must match what actually gets DEPLOYED. The list pinned Kubernetes
#      v1.32.3 while the apt repo installs the current 1.32.x (v1.32.13 on
#      2026-08-16), so every core image was a cache miss and came from
#      registry.k8s.io anyway.
#
#   2. It must match the CHARTS. build-iso.sh stages helm charts into the
#      darksite; if those resolve to a different version than the images here,
#      the cluster pulls the chart's images over the network and the cache is
#      decorative. Chart versions in build-iso.sh and the versions below are
#      one decision — change them together.
#
#   3. It has to be complete. Cilium's own DaemonSet needs cilium-envoy, which
#      was never listed, so it was fetched from quay.io on every deploy. The
#      reliable way to extend this file is to ask helm, not to guess:
#
#        helm template x cilium/cilium --version <v> \
#          | grep -oE '^\s+image:\s*"?[^"]+' | sed 's/.*image:\s*//'
#
# An install with these cached still reached for ~129 images off the public
# internet before this was fixed (fiend, 2026-08-16).
#
# Format: registry/image:tag — one per line, # for comments.
