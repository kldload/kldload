# target-fedora-extras.txt — Fedora-specific additions to the shared EL
# package sets. These are the packages needed on Fedora targets that either
# don't exist on EL or whose names differ enough that shared EL sets miss them.
#
# Most important: the full DKMS toolchain for building OpenZFS from source.
# OpenZFS upstream hasn't published a prebuilt release RPM for fc43 yet
# (as of 2026-04), so fedora installs compile ZFS from the kernel-devel
# headers at install-time. Without this chain, offline fedora installs
# would fail at the ZFS build step.

# Cert trust — nss-tools ships `certutil`, which kldload-trust-cert uses to
# seed Chrome's per-user NSS DB (~/.pki/nssdb) + the system store so the
# kldload-webui self-signed cert on https://localhost:8443 is trusted silently
# (no interstitial on every dashboard tile). It's already in the Debian darksite
# (target-base.txt) and the Fedora desktop install list (profiles.sh), and there
# is a firstboot healing net that re-attempts `dnf install nss-tools` — but on
# F44 that net FAILED because the .rpm was never mirrored here: only the repo
# *metadata* carried nss-tools (as a transitive dep), so the completeness gate's
# metadata dry-run passed while the actual file was absent (10.100.10.124
# 2026-06-14: "Could not open file .../nss-tools-3.123.1-1.fc44.x86_64.rpm",
# kldload-tls-cert.service then churned to start-limit-hit). Listing it here
# forces the .rpm into the snapshot so the offline install can land it.
nss-tools

# Fedora's NATIVE default GNOME wallpaper (distinct day/night art). REQUIRED on

f44-backgrounds-gnome

# Boolean/rich-dep companions that `dnf download --resolve --alldeps` does NOT
# follow (it ignores `(X if Y)` conditional deps). qemu pulls passt, and passt
# carries `Requires: (passt-selinux if selinux-policy-targeted)`. Since the
# target installs selinux-policy-targeted, that condition fires at install time
# and demands passt-selinux — which, if absent from the mirror, makes the ENTIRE
# offline dnf transaction unsatisfiable, taking the zfs pass-3 install down with
# it (F44 b-2026-06-13: install aborted "target will not boot" although zfs 2.4.3
# resolved fine). Listing it explicitly pulls it in the same snapshot as passt
# so the version matches. NOTE: if other rich-dep companions surface, add them
# here too, or build a post-mirror closure gate that dry-run-installs the full
# set against the darksite and reports gaps.
passt-selinux

# Video acceleration. Two names here resolved NOWHERE on F44 -- not in Fedora,
# not in RPM Fusion -- and had been quietly doing nothing: mesa-vdpau-drivers
# and nvidia-vaapi-driver. A name-only mirror query cannot fail loudly on a
# package that does not exist, so they read as coverage while providing none.
# Verified 2026-08-28 by resolving every name against a real F44 container with
# both RPM Fusion repos enabled.
#
# What actually delivers accelerated playback, and does resolve:
#   mesa-va-drivers-freeworld  VA-API for AMD/Intel WITH the patented codecs.
#                              Stock mesa-dri-drivers Provides mesa-va-drivers,
#                              but only the free subset -- so H.264/H.265 fell
#                              back to software on every AMD and Intel box.
#   libavcodec-freeworld       the H.264/H.265/AAC decoders themselves. Fedora
#                              ships -free builds with those stripped, which is
#                              why ordinary video would not play at all.
# Both confirmed to coexist with the free stack (no conflicts, no swap needed);
# RPM Fusion free+nonfree are already enabled by build-darksite-fedora.sh.
libva-intel-driver
mesa-va-drivers-freeworld
libavcodec-freeworld
# gstreamer1-plugin-libav is the ffmpeg bridge, and it is why the earlier note
# about "gstreamer1-libav ... satisfied through Provides" was true and useless:
# gstreamer1-libav is not a package, it is a Provides OF gstreamer1-plugin-libav.
# Querying the name a mirror cannot see meant nothing was ever mirrored, and
# GStreamer -- which is what GNOME Videos and file previews use -- could not
# reach libavcodec at all. It is in stock Fedora, not even RPM Fusion.
gstreamer1-plugin-libav

# Versionlock plugin — the F44 anti-brick. firstboot (kldload-firstboot ~1508)
# runs `dnf install python3-dnf-plugin-versionlock` then locks kernel*/zfs* at
# the shipped NVRs so a later `dnf upgrade` can't bump the kernel past what the
# release ZFS builds against. On an OFFLINE install this MUST come from the
# mirror — and it was absent: only the repo metadata carried it, so the
# completeness gate's dry-run passed while the actual .rpm (and its deps
# python3-dnf-plugins-core + python3-dateutil) were missing. Hardware
# 2026-07-24 (10.100.10.108): firstboot logged "versionlock plugin install
# failed — core packages NOT locked", leaving the substrate unlocked. Listing
# it here forces the .rpm + deps into the snapshot. (Same class as nss-tools.)
python3-dnf-plugin-versionlock
fzf
pv
mbuffer
