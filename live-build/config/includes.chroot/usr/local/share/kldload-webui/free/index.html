System overview
kldload 1.3.0 — Kernel-Loaded Workstation
Fedora 44 on the Linux 7.0 kernel, OpenZFS 2.4.3 on root, dnf5. One URL, one cert, every service — the whole stack runs in the kernel.
For any dnf / apt / pacman Linux: Fedora · RHEL · Rocky · CentOS · Debian · Ubuntu · Arch. Reproducible, 100% air-gapped install.
What’s new in 1.3.0
• Any dnf / apt / pacman Linux — one USB, ZFS-on-root across Fedora 44 (primary) / RHEL / Rocky / CentOS / Debian / Ubuntu / Arch; reproducible 100%-darksite offline install
• Compose your own — capability toggles above the Install button: KVM, Kubernetes, klab, AI (Bob), observability, ZFS lab, WireGuard — mix & match, point-and-shoot
• Native-app dashboards — every web tool opens as its own standalone window with the correct dock icon (Chrome app-mode + Wayland app_id), not a browser tab
• NVIDIA — akmod (signed, Secure-Boot-capable) + first-boot healing net builds & loads the driver for native resolution
• eBPF / CO-RE cockpit — libbpf-tools (BTF) work on the 7.0 kernel where legacy bcc can't compile, + bpftrace + Tetragon, in sysdiag
• In-kernel networking — WireGuard 4-plane microsegmented mesh (mgmt / k8s / data / enrollment)
• ZFS data lake — snapshots, boot environments, instant clones, NFS/iSCSI; ABI versionlocked so dnf update can't brick ZFS/NVIDIA
• KVM + local Kubernetes + klab — kvm-create/snap/clone, kube-cluster (control-plane + workers on ZFS clones), multi-distro blue-green goldens
• Bob — local GPU LLM assistant, offline, voice via Chrome Web Speech
• Fail-loud install — critical-package verify gate (no silent --skip-broken), firstboot healing nets, every pass verified against the rpm db
• Desktop — GNOME on Wayland, per-distro native wallpaper, Chrome, gnome-terminal sysdiag, Steam
• The whole stack in the kernel: GPU, eBPF, WireGuard, and an endless ZFS data lake — reproducible, air-gapped, on any distro.

➕ Install kldload Elsewhere One-shot bootstrap — click to copy
Apple Silicon Mac (M1/M2/M3)
From macOS: install Fedora Asahi Remix, then run this from Asahi to layer kldload
curl -sL https://raw.githubusercontent.com/kldload/kldload-free/main/live-build/config/includes.chroot/usr/local/share/kldload-ansible/playbooks/asahi-convert.yml | sudo tee /tmp/kc.yml > /dev/null && sudo dnf install -y ansible-core git && sudo ansible-playbook /tmp/kc.yml
Prereq: curl https://alx.sh | sh on macOS first, pick Fedora Asahi whole-disk
Any existing Linux host
Layer kldload tools onto a running Debian/Ubuntu/Fedora/Rocky/CentOS system
git clone https://github.com/kldload/kldload-free /tmp/kldload && sudo cp /tmp/kldload/live-build/config/includes.chroot/usr/local/bin/* /usr/local/bin/ && sudo cp -r /tmp/kldload/live-build/config/includes.chroot/usr/local/share/kldload-ansible /usr/local/share/
Fresh bare-metal x86_64
Burn this USB to /dev/sdX on a target machine
sudo umount /dev/sda* 2>/dev/null; sudo wipefs -a /dev/sda && sudo dd if=/path/to/kldload-1.1.0-x86_64.iso of=/dev/sda bs=4M status=progress oflag=direct conv=fsync && sync
aarch64 VM on any Mac (UTM/Parallels)
Build the ARM ISO on this host, then attach in your VM manager
ARCH=aarch64 ./deploy.sh builder-image && ARCH=aarch64 PROFILE=kvm ./deploy.sh build
