What you get

The platform, not just the OS.

Most installers stop at the rootfs. kldload keeps going — boot environments, snapshots, mesh VPN, eBPF tracing, NVIDIA, container runtime, and an instant-clone KVM lab — all wired and signed before first boot.

Z

ZFS on root, properly

Native rpool, dataset layout, sanoid-managed snapshots, ZFSBootMenu rollback. Clone, snapshot, rewind — zero rebuild.

⚡

100ms VM clones

klab spawns a full Linux VM from a golden ZFS image in under a second. Tear it down, spawn ten more. Zero copy.

🔒

Secure Boot, signed chain

shim → grub → vmlinuz → zfs.ko, all signed. Per-install MOK leaf cert, enrolled at first boot via MokManager.

⌘

Offline darksites

RPM and APT mirrors baked in. Install behind air gaps, in proxy hell, or off your phone tether — same ISO.

⌗

WireGuard mesh

Each node generates its own keypair, registers via the manager, gets a /24 in the cluster mesh — at install.

⚙

K8s + Cilium eBPF

kube-cluster bootstraps a control plane and N workers on ZFS instant clones, with Cilium eBPF networking out of the box.

Install

Boot the USB. Pick a profile. Walk away.

The installer is one Python file and one HTML file. No Anaconda, no debian-installer screens, no Y/N text walls. Pick a distro, pick a profile, click Install. You'll be at a desktop or an ssh prompt in twelve minutes.

  • Three profiles: desktop, server, core
  • Two editions: free (everything) and core (ZFS only)
  • Export to qcow2 / vmdk / vhd / ova / raw as a golden cloud-init image
  • Single static answers file for headless / scripted installs
install.sh — answers
# headless install — single env file
PROFILE=desktop
DISTRO=fedora
EDITION=free
DISK=/dev/nvme0n1
HOSTNAME=kldload-node
ZFS_ENCRYPT=1

# or interactive
$ kldload-install-target
  ✓ partitioned /dev/nvme0n1
  ✓ created rpool · raidz2 · 1.8T
  ✓ bootstrapped fedora 44 from darksite
  ✓ signed kernel + initramfs
  ✓ enrolled MOK · ready to boot
$ reboot
